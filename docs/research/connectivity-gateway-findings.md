# Gateway and agent connectivity research

**Document ID:** RES-CONNECT-01. **Status:** primary-source research and Custos design inference, 2026-09-27. Vendor documentation can move independently of deployed releases; pin binary/source revisions in implementation spikes. No chain in this page is claimed as production-tested by Custos.

## Specific operational constraints from primary sources

- Goose's built-in Developer extension can run commands and modify files; its own docs warn that autonomous mode can do so without approval. Custos must set an explicit external-agent control mode and avoid claiming governed execution when a native tool path remains open. [Goose extensions](https://github.com/aaif-goose/goose/blob/main/documentation/docs/getting-started/using-extensions.md).
- MCP's host has the consent/security responsibility, and tool annotations should be considered untrusted unless the server itself is trusted. Therefore a tool catalog must classify real effects from verified adapters/policies rather than server-provided descriptions alone. [MCP architecture](https://modelcontextprotocol.io/specification/2025-11-25/architecture), [MCP tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools).
- Agentgateway virtual-model failover depends on concrete target health eviction; the triggering request can fail unless retry is configured. Custos must count each actual attempt and avoid allowing two independent fallback owners in one pool. [Virtual models](https://agentgateway.dev/docs/standalone/latest/documentation/llm/virtual-models/).
- Agentgateway's documented per-key LLM budget is charged after response, so a request crossing the threshold can finish, and a request without required usage can go uncharged. Custos needs a conservative pre-dispatch reservation and a post-response settlement, with Unknown cost retained when usage is absent. [Budget limits](https://agentgateway.dev/docs/standalone/latest/documentation/llm/cost-controls/budget-limits/).
- In Agentgateway's documented `mcpAuthorization` policy, tool name/target may be available before dispatch while arguments are described as post-request data. Exact argument/payload checks therefore belong in Custos's pre-effect path unless a pinned gateway version proves otherwise. [MCP authorization](https://agentgateway.dev/docs/standalone/latest/documentation/configuration/security/mcp-authz/).
- 9Router's compatibility and smart-routing docs describe fallback; a strict/pinned route is a conformance condition, not a label Custos may assume. Combined Agentgateway→9Router request, stream, tool-call and usage translation needs an explicit test matrix. [Architecture](https://github.com/decolua/9router/blob/master/docs/ARCHITECTURE.md), [smart routing](https://github.com/decolua/9router/blob/master/gitbook/content/en/features/smart-routing.md).

## Resulting Custos boundaries

Three port families must remain separate: `ModelPort` for inference, `AgentRuntimePort` for an external agent loop/session, and `ToolPort`/MCP client for capabilities. ACP/A2A/CLI adapters are not inferred from a model API. A user can choose a specific model, account pool or external agent when a conforming adapter exists, but the chosen connection carries a declared control mode: `Custos-mediated`, `Provider-governed` or `Observe-only`. Only the first may claim pre-effect Custos enforcement over every tool invocation.

No additional gateway is a prerequisite for F1 read-only explain or F2 controlled bug fix. Add one only if it reduces operational burden or enables a measured use case without obscuring route, tool or effect provenance.
