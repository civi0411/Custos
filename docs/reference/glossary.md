# Custos Canonical Glossary & Domain Terms

> **Classification:** Domain Terminology Reference  
> **Source of Truth:** Authoritatively defined in [Custos Master Specification](../../Custos.md).  
> **Directory Index:** See [Custos Developer Reference](README.md).

This glossary establishes the normative definitions for architectural terms, domain models, and protocols across the Custos platform.

---

### ActionIntent
A structured proposal generated by a worker or model indicating an intent to perform an external side effect (e.g., file write, shell command, network request). An `ActionIntent` contains target parameters, rationale, and an argument hash, but possesses **zero execution authority** until vetted by the Authority Engine.

### Ambient Authority
An architectural anti-pattern and security vulnerability where an agent inherits execution privileges from its ambient environment rather than requiring explicit, granular capability tokens for each specific invocation. Custos explicitly eliminates ambient authority.

### Assurance Label
A metadata tag indicating the level of runtime control and sandboxing applied to an operation (`custos-mediated`, `provider-governed`, `observe-only`, `unknown`).

### CAS (Content-Addressed Storage)
An immutable storage subsystem where files and artifacts are identified and retrieved strictly by their cryptographic hash (SHA-256). Ensures provenance, tamper-proofing, and deduplication across task executions.

### CheckpointPolicy
A configurable persistence policy defining when and how durable snapshots of a task's state, DAG progress, and CAS artifacts are committed to persistent storage.

### Completion Gate
An independent verification barrier inside the Trusted Kernel. It is the **sole authority** permitted to transition a task state to `Succeeded` by validating required evidence against task criteria. Models cannot mark their own completion.

### ContinuationPacket
A cryptographically sealed (SHA-256) data structure encapsulating the minimal essential state, task summary, and memory anchors required to pause and safely resume a task across sessions, daemon restarts, or different AI providers.

### Context Compiler
An 8-step pipeline responsible for gathering, filtering, ranking, and packing source code, historical facts, and project guidelines into an immutable `ContextPack` within the allowed model token budget.

### DecisionContract
A formal specification capturing the parameters, bounds, and criteria agreed upon between the user and the system before delegated execution begins. Standardized replacement for ambiguous heuristics.

### Delegation Diminishment
The cryptographic and domain rule stating that capability tokens granted to child tasks or sub-agents must be a strictly diminished subset of the parent agent's authority. Rights can never expand downstream.

### EffectAttempt
A tracked runtime execution of an authorized permit. Manages states across the execution lifecycle (`Prepared` $\rightarrow$ `Dispatching` $\rightarrow$ `ObservedSuccess` \| `ObservedFailure` \| `Uncertain`).

### EphemeralQuery
A transient user request (e.g., quick question, explanation) handled within an interaction session that does not mutate files, require persistent task tracking, or initiate side effects.

### EvidenceRecord
A first-class empirical record documenting verification proof for a criterion. Classified into Fact (deterministic tool output), Extraction (parsed structural data), or Semantic (model judgment with confidence bounds).

### HumanAvailability
A task configuration flag (`Present` vs `Absent`) specifying whether the human user is actively at their workstation to approve escalated permits, or if the daemon must park blocked actions until the user returns.

### IBCT (Invocation-Bound Capability Token)
A cryptographically bound token valid for exactly one tool invocation, tied to a specific agent identity, parameter hash, and delegation depth limit.

### MCP Hub
The daemon subsystem that manages connections, lifecycles, OAuth 2.1 authentication, and tool routing for external Model Context Protocol servers.

### ModelAttempt
A single recorded interaction with an inference provider. Logs input prompt hash, output response, transport protocol, latency, token consumption, and financial cost.

### Outbox Pattern
A persistence design pattern ensuring atomic consistency between SQLite state transitions and external side effects by durable staging of outbound messages before physical dispatch.

### Pack (Domain Pack)
A domain-specific bundle (e.g., `Engineering`, `Research`, `Assistant`) providing specialized toolsets, verifier profiles, workflow DAGs, and prompts.

### Permit (ExecutionPermit)
A cryptographically signed, single-use authorization artifact issued by the Authority Engine. Binds a specific action ID to an exact argument digest and expiration deadline.

### Receipt (ExecutionReceipt)
A verifiable proof record produced after tool execution, capturing the output digest, execution duration, exit status, and error details.

### Reconciliation
The automated crash-recovery process executed upon daemon restart to resolve uncertain side-effect attempts through external status polling or idempotent post-reads.

### System 1 (S1 Fast Fabric)
The lightweight, low-latency heuristic tier (SLMs or rule engines) responsible for rapid classification, intent detection, and initial routing. S1 operates with strict `abstain` boundaries and cannot sign permits.

### System 2 (S2 Deliberative Planner)
The advanced reasoning tier (frontier LLMs) responsible for complex task decomposition, code generation, multi-step problem solving, and evidence production.

### Taint Tracking
The security mechanism that labels all data ingested from external or untrusted sources as `Taint::Untrusted`, strictly preventing untrusted content from being interpreted as operational control instructions.

### Task / TaskContract
The fundamental durable unit of work in Custos. Unlike a session, a task persists across client disconnects, managing its own lifecycle FSM, budget, scope, and acceptance criteria.

### TaskCandidate
A proposed plan of action surfaced during exploratory interaction. May be promoted to a committed `TaskContract` once approved by the user.

### Task FSM
The canonical Finite State Machine governing a task's lifecycle: `Draft` $\rightarrow$ `Queued` $\rightarrow$ `Running` $\leftrightarrow$ `Blocked` $\rightarrow$ (`Succeeded` \| `Failed` \| `Cancelled`).

### Transaction Boundaries (T1–T5)
The 5 formal database and operational boundaries dividing a task lifecycle into isolated, recoverable transactional segments.

### Worktree Isolation
The practice of executing filesystem mutations and automated tests inside dedicated, ephemeral git worktrees (`isolated_worktree`), preventing dirty state from polluting the primary repository branch.
